# Contributing to tokenAtlas

Thank you for helping make AI usage data easier to understand. Contributions can
be bug reports, reproducible examples, tests, documentation, translations or code.
Financial support is optional and never a condition for reporting an issue or
having a pull request considered.

## Before you start

Read `AGENTS.md`. The application is desktop-only and its approved interface is a
constraint. Discuss larger features, accounting changes, new integrations and UI
changes in an issue before implementing them. Do not submit private transcripts,
account identifiers, email addresses, authentication material or database dumps.
Use small, synthetic fixtures with an explicit expected result.

For bugs, describe the app version/commit, system, reproduction steps, expected
and actual behaviour, and which numbers are source readings versus estimates.
A missing record is not proof of zero usage or a provider billing error.

## Pull requests

Fork or use a branch, keep the change focused, explain the reason and scope, and
include tests appropriate to it. Separate changes to ingestion/accounting from
visual changes. State exactly which checks ran and which could not run. Discuss
any dependency additions and their licenses. Preserve existing third-party notices.

K_NODE maintains the official direction and releases. A PR may need revision or
may be declined; proposing a change does not give write access to the main branch.
`CODEOWNERS` identifies a reviewer but does not enforce branch protection by itself.
The maintainer must configure rules and avoid a rule requiring self-approval of
maintainer-authored PRs. No branch protection settings are changed by these files.

unless explicitly agreed otherwise before submission. Only submit work you have
the right to contribute, including any required employer permission. Existing
author notices must be retained. Contributions do not transfer copyright ownership
to the maintainer, and this project does not request a separate copyright assignment.

## Support and independence

Sponsorship supports development, not PR priority or favourable analytical results.
Company sponsorship, optional support and commissioned work are separate choices.
The website's proposed tiers are not active until the relevant profiles and terms
have been verified. Report security-sensitive findings privately through an
explicitly published security contact; do not place exploitable details or secrets
in a public issue. Until that contact exists, ask the maintainer for a private
channel without attaching the sensitive material.
